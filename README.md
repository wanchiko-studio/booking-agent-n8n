# Booking Agent — n8n + LLM + Airtable

Разговорный ИИ-агент, который принимает первичное обращение клиента, ведёт диалог, подбирает время и **сам оформляет запись** — без участия администратора.

Собран для стоматологических клиник: там основная потеря заявок происходит вечером и в выходные, когда никто не отвечает в первые минуты.

**Статус:** собран под запрос стоматологической клиники. Перед передачей я ещё раз прогнал тесты, нашёл ошибки и исправил их (подробно ниже). До запуска у клиента проект не дошёл, поэтому здесь рабочее демо, а не продакшен.

---

## Что делает

1. Клиент пишет в чат (Telegram / виджет на сайте)
2. Агент отвечает на вопросы по услугам, ведёт диалог с памятью в пределах сессии
3. Выясняет, что нужно, и предлагает свободное время
4. **Вызывает инструмент `Book_Appointment`** и создаёт запись в Airtable
5. Параллельно логирует обращение в таблицу заявок

Мультиязычный — демо есть на английском и на русском.

## Граф workflow (6 нод)

| Нода | Тип | Роль |
|---|---|---|
| `When chat message received` | `chatTrigger` | вход, вебхук чата |
| `AI Agent` | `langchain.agent` | оркестрация диалога и вызов инструментов |
| `OpenRouter Chat Model` | `lmChatOpenRouter` | модель; OpenRouter даёт переключение между Claude / GPT без переписывания графа |
| `Simple Memory` | `memoryBufferWindow` | контекст диалога в пределах сессии |
| `Book_Appointment` | `airtableTool` | **инструмент**, который агент вызывает сам, когда данных достаточно для записи |
| `Log to Airtable` | `airtable` | фиксация обращения |

Ключевое решение — запись оформляется **инструментом агента**, а не жёстким шагом в конце сценария. Агент сам решает, когда собрал достаточно данных. Это отличает агента от линейного чат-бота по кнопкам.

## Инженерная история (главное здесь)

На тестах вылезли две вещи, и обе чинились не кодом:

**1. Агент выдумывал цены.** Называл суммы, которых нет в прайсе — классическая галлюцинация, когда модель заполняет пробел вместо того, чтобы сказать «не знаю». Лечилось не постобработкой ответа, а переработкой системного промпта и структуры данных, которые агент видит перед ответом: прайс подаётся явно и ограниченно, плюс прямой запрет называть цену вне списка. Выдуманные цены исчезли полностью.

**2. Путались часовые пояса при записи.** Время бралось и записывалось в разных зонах, запись уезжала. Чинилось нормализацией времени до одной зоны на входе в инструмент.

Вывод, который я забрал: в агентных системах большая часть багов живёт не в коде, а в том, что модель видит перед тем, как ответить.

## Как запустить

1. Импортировать `booking-agent-workflow.json` в n8n (Workflows → Import from File)
2. Подставить свои креды — в файле стоят плейсхолдеры:
   - `REPLACE_WITH_YOUR_OPENROUTER_CRED` → OpenRouter API
   - `REPLACE_WITH_YOUR_AIRTABLE_CRED` → Airtable PAT
3. В Airtable завести базу с таблицей записей (имя/контакт/услуга/время/статус)
4. Активировать workflow и открыть чат
